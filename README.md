# LokiBench: 개인 로컬 이슈 트래커

## 프로젝트 소개

#### 📌 불편했던 점

- 지난 작업의 해결 과정을 다시 찾기 어려움
  - 기록은 남겨도 어디에 두었는지 몰라 비슷한 문제를 처음부터 다시 고민함
  - 문서와 자료가 흩어져 있어 AI에게 맥락을 매번 다시 설명해야 함
- 여러 작업의 진행 상황을 머릿속으로만 관리함
  - 어떤 작업이 진행 중이고 어떤 작업이 멈춰 있는지 매번 떠올려야 함
  - 학습할 내용이나 추가 개선 사항을 따로 쌓아 둘 곳이 없어 잊어버림

<br />

#### 📌 해결 방식

- 작업 기록을 정해진 구조로 한곳에 쌓음
  - 마일스톤마다 배경, 해결 방안, 관련 자료 위치를 남겨 지난 해결 과정을 바로 꺼내 봄
  - 기록이 로컬 DB 하나에 구조화되어 모여 있어, 나중에 AI로 지난 맥락을 한 번에 되짚음
- 진행 상황을 머릿속이 아니라 화면에 둠
  - 여러 프로젝트의 진행 중, 대기 중인 작업을 한 화면에서 보고 다음에 손댈 작업을 바로 고름
  - 학습할 내용, 추가 개선 사항까지 개인 백로그로 쌓아 두고, 여유가 생길 때 꺼내 진행함

## 개발 목표

#### 📌 판단 원칙

- 그동안 불명확하고 때마다 달랐던 판단 기준을 작업을 거치며 명확한 원칙으로 정리
- 컴포넌트 추상화 높이, 모듈과 레이어를 나누는 지점, 예외와 테스트 범위의 판단 기준을 고민하고 문서로 남김
- 선택지마다 근거와 반례를 따져 보고, 트레이드오프를 어떻게 풀었는지 과정을 함께 기록

<br />

#### 📌 모노레포와 모듈 구성

- Turborepo를 활용해 모노레포와 모듈 구성을 효율적으로 가져가는 방법을 찾음
- 한 저장소 안에서 여러 앱과 패키지의 의존성을 관리하는 방법을 익힘 (워크스페이스 연결, 버전 통일)
- 작업 순서와 캐시 설정을 다듬으며 빌드와 테스트를 더 효율적으로 돌릴 수 있는 지점을 찾아 개선
